# ESP32-C3 Bring-up Session — 2026-11-04

**Disposition:** ESP32-C3 workstream closed and archived for this project iteration.  
**Next platform:** ESP32-S3 family selected by the project owner. Exact board/module variant remains to be identified.  
**Scope:** serial baseline, INMP441 I²S diagnostic, and Wi-Fi SoftAP/HTTP diagnostic.

This report records the observed results. It does not infer a hardware root cause where the tests did not establish one. The archived raw transcripts redact the test credential, nearby Wi-Fi SSIDs/BSSIDs, local account paths, and the board MAC address.

- PlatformIO Core: 6.2.0.

- PlatformIO board definition: esp32-c3-devkitm-1, used as a compatible starting definition for the Super Mini; it does not identify the exact clone layout.

- USB device ID: 303a:1001; serial device path used: /dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_[REDACTED]-if00.

## Test 1 — Serial baseline

**Result: PASS for the observed test window.**

- Serial monitor: 115200 baud.
- Serial-only firmware compiled and uploaded successfully.
- Upload verification reported a matching flash hash.
- Heartbeat observed from uptime 11 s through 63 s.
- Free heap remained at 310,948 bytes in the captured heartbeat window.
- A separate earlier baseline observation recorded 31 seconds and 310,916 bytes free heap.

This verifies the serial diagnostic path during the observed periods. It does not prove long-duration reliability.

## Test 2 — INMP441 I²S raw diagnostic

**Result: microphone data observed; full audio-format validation remains incomplete.**

Configuration recorded:
- I²S master RX, I²S0.
- Configured sample rate: 16,000 Hz.
- 32-bit I²S slots; left channel selected.
- DMA: 4 buffers, 256 samples per buffer.
- BCLK GPIO4, WS GPIO5, SD GPIO3.
- Diagnostic converted the captured 32-bit word to a signed 16-bit value using the upper sample bits.

Captured observations:
- Reported measured rate: approximately 16,000–16,016 samples/s.
- Reported RMS values across windows: approximately 413.7–8,226.0.
- Maximum reported peak: 32,758.
- Reported clipped-sample count: 0 in the captured windows.
- Displayed raw I²S words consistently had their lowest byte equal to 00.

Interpretation:
- The INMP441 path produced changing sample data and the diagnostic completed without a reported I²S read error in the captured output.
- The observed rate is close to the configured 16 kHz rate.
- The sample alignment/channel interpretation is provisional. The raw-word pattern is evidence, not a complete proof of the selected PCM representation.
- The test windows were not consistently labelled as silence, speech, or controlled acoustic input. Therefore RMS values cannot be treated as a measured noise floor or SNR.
- Some reported peaks approached full scale even though the clip counter remained zero. This requires a controlled follow-up if this microphone path is reused.

The diagnostic build succeeded. Build summary: RAM 14,956 bytes (4.6% of 327,680); flash 261,680 bytes (20.0% of 1,310,720). Upload completed and flash hashes were verified. The build emitted a deprecation warning for I2S_COMM_FORMAT_I2S.

## Test 3 — Wi-Fi SoftAP and HTTP diagnostic

**Result: FAILED acceptance criterion — SSID was not detected by Ubuntu. Root cause not isolated.**

Configured test:
- SSID: DIY-Mic-Setup.
- WPA2 test credential was used; the credential is redacted from the committed source and logs.
- Channel: 6.
- Hidden SSID: false.
- Maximum clients: 4.
- AP address: 192.168.4.1/24.
- Arduino WiFi and WebServer libraries.

Build and upload:
- Build succeeded.
- RAM: 39,212 bytes (12.0% of 327,680).
- Flash: 755,000 bytes (57.6% of 1,310,720).
- Firmware image upload completed; hash verification succeeded.

Runtime observations:
- Serial status repeatedly reported Wi-Fi mode 2 (WIFI_AP).
- Serial status repeatedly reported AP IP 192.168.4.1.
- The status code prints the AP IP only while its apStarted flag is true; this indicates that the WiFi.softAP() call returned true in that firmware run.
- Free heap remained approximately 229,092 bytes during the captured status window.
- Uptime advanced through the captured 36–105 s interval and later observations, without a reset visible in those excerpts.
- AP client count remained 0.
- The initial boot messages, including the explicit success line, were not captured because the serial monitor was opened after startup.
- Repeated Ubuntu nmcli scans listed other nearby networks but did not list DIY-Mic-Setup.
- No successful client association was recorded.
- The HTTP root and health endpoints were implemented in the diagnostic source, but HTTP connectivity was not verified because no client joined the AP.
- WebSocket and audio streaming were not implemented or tested in this experiment.

**Conclusion:** The configured AP mode and API-level startup path reported success, but the required visible SSID/client-discovery criterion failed. This does not establish whether the cause was firmware configuration, RF/beacon behavior, board/antenna hardware, or another factor. Do not label the ESP32-C3 silicon as conclusively defective.

## USB observations

- Linux enumerated the ESP32 USB Serial/JTAG device as 303a:1001.
- Earlier kernel logs showed repeated USB disconnect/re-enumeration events during the Wi-Fi diagnostic session.
- A later serial-only firmware test produced stable heartbeat output over the captured 53-second window.
- The logs do not establish the cause of the earlier USB reconnect events.

## Final disposition and next work

1. Close the ESP32-C3 implementation workstream for this iteration.
2. Preserve the C3 source, diagnostic projects, build records, and raw logs as an archive. Do not delete the history.
3. Continue with the ESP32-S3 family as the next target.
4. Before writing S3 firmware, identify the exact board/module, flash size, PSRAM presence, USB interface/routing, board ID, and available GPIOs.
5. Repeat a serial-only baseline first, then test SoftAP SSID visibility before integrating I²S or the receiver.
6. Keep the INMP441 as the microphone candidate; today's I²S results are provisional evidence of capture, not a completed audio-quality acceptance test.
