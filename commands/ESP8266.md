# ESP8266 Command Guide

**Target:** NodeMCU ESP8266 serial bring-up project.  
**Project directory:** `firmware/esp8266/serial-bringup/`.

The serial bring-up firmware checks the PlatformIO build/upload/serial path. It is not the owner-reported V0.5 live microphone firmware.

## 1. Open the project

Run in Ubuntu Terminal:

```bash
cd ~/Projects/DIY-Mic/firmware/esp8266/serial-bringup
```

Run PlatformIO commands from this directory because it contains `platformio.ini`.

## 2. Build, upload, and monitor

| Command | Purpose | Use case |
|---|---|---|
| `pio project config` | Print resolved project settings | Check board and framework |
| `pio run` | Compile without uploading | Check the build |
| `pio run -t clean` | Remove generated build files | Clean rebuild |
| `pio run -t upload` | Build and upload to NodeMCU | Flash the serial test |
| `pio device list` | List serial devices | Find the USB port |
| `pio device monitor --baud 115200` | Open serial monitor | Read test output |

If needed, specify the port:

```bash
pio run -t upload --upload-port /dev/ttyACM0
pio device monitor --port /dev/ttyACM0 -b 115200
```

The port `/dev/ttyACM0` is an example from earlier development notes; check the current device list before using it.

Expected serial output from this repository's serial test:

```text
DIY-Mic ESP8266 serial bring-up test
Board and serial monitor are running.
```

## 3. Check host-side tests

From the repository root, run:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

See [Host Tests](HOST-TESTS.md) for PCM inspection.

## 4. Historical V0.5 prototype

The owner-reported V0.5 prototype used NodeMCU ESP8266 + INMP441 + Wi-Fi AP + WebSocket + browser Web Audio API. The receiver page was `http://192.168.4.1` and the WebSocket server used port 81. The exact V0.5 firmware/webpage source is not currently verified in this serial bring-up folder.

Do not treat successful serial bring-up as proof of I²S capture, Wi-Fi audio streaming, Android playback, latency, or microphone quality.
